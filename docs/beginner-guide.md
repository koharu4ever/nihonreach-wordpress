# 新手操作指南

## 先理解三个词

**后台**是你输入产品内容的地方。**插件**决定“有哪些业务功能”：本站的产品、分类和型号由 NRC 插件提供。**主题**决定“顾客看到什么样子”：本站在官方父主题上创建了自己的子主题，更新父主题不需要覆盖自己的模板。

## 用 VS Code 开发：和原 NihonReach 一样

1. 打开 Docker Desktop。
2. 用 VS Code 打开 `C:\dev\nihonreach-wordpress`，不是旧 Laravel 文件夹。
3. 按 `Ctrl+Shift+P`，输入并选择 `Dev Containers: Reopen in Container`（在容器中重新打开）。若命令不存在，在扩展页面安装微软的 Dev Containers。
4. 首次等待工具镜像构建；已经装好的产品内容不会被重置。
5. 左下角显示 `Dev Container: NihonReach WordPress` 后，打开一个新终端。
6. 终端在 `/work`，可直接输入 `php -v`、`composer --version`、`wp core version`，不需要自己加 Docker 前缀。
7. 左侧打开 `plugins/nrc-catalog` 或 `themes/nrc-child` 修改代码；保存后在浏览器刷新查看。

**分清两个终端：**容器里的 Bash 用于 PHP、Composer、WP-CLI；Windows PowerShell 用于 Docker 启停、备份脚本和独立数据库测试。容器里没有 Docker 控制权限，不能从里面运行 `docker compose`。

关闭 Dev Container 窗口会停止开发站，但保留全部数据。下次重新打开同一 Dev Container 即可继续。若只是修改产品内容，直接打开浏览器后台即可，无需打开代码编辑器。

## 第一次打开

1. 打开 Docker Desktop，等它启动完成。
2. 项目已运行时，用浏览器打开 `http://127.0.0.1:8081/`。
3. 点击「探索产品目录」，看到第 1 页 9 个产品；滚到下面点击「下一页」，看到剩余 3 个。
4. 点击产品名称，可以看到型号、分类、图片与介绍。
5. 这是虚构 Demo，联系页没有真正发送表单。

网页打不开时，在 PowerShell 输入：

```powershell
cd C:\dev\nihonreach-wordpress
docker compose up -d --wait
```

## 登录后台

1. 浏览器打开 `http://127.0.0.1:8081/wp-admin/`，会进入中文登录页。
2. 用 Windows 文件资源管理器打开项目中的 `.local` 文件夹。
3. 用记事本打开 `credentials.txt`，读取用户名和密码。不要把这个文件提交到 Git 或发给别人。
4. 将用户名与密码填入登录页，点击「登录」。
5. 看到左侧「仪表盘、文章、媒体、页面、产品」等菜单即登录成功。

本机演示拦截邮件，所以「忘记密码」不会发真实邮件。不要依赖邮件重置；先妥善保存本地凭据。

## 修改已有产品

1. 左边点击「产品」→「所有产品」。不要进入「文章」。
2. 点击「四刃平底立铣刀 6mm」等产品名称。
3. 最上面的框是产品名称；中间大框是正文介绍。
4. 找到「产品型号」框，输入例如 `EM-06-4F`。
5. 在右边「产品分类」勾选分类；右边「特色图片」决定产品卡片与详情主图。
6. 点击右侧「更新」。看到「文章已更新」是 WordPress 通用提示，这里更新的是产品。
7. 查看页面上方是否另有红色型号错误；错误时旧型号保留，正文可能已保存。
8. 点击「查看文章」或产品固定链接，到前台查看效果。

型号可以清空。非空必须仅由 `A–Z`、`0–9` 和 `-` 组成，最多 32 个字符。小写、空格和中文会拒绝，而不是偷偷改掉。可以试输入 `bad model` 观察红色反馈，再输入正确值保存。

## 添加新产品与图片

1. 左侧「产品」→「新增产品」。
2. 输入标题、正文、产品型号，选择产品分类。
3. 点击「设置特色图片」→「上传文件」→「选择文件」，从电脑选一张允许使用的产品图片。
4. 为图片填写能描述产品的替代文本，点击「设置特色图片」。
5. 点击右侧「发布」。如果只是练习，先点「保存草稿」。
6. 回前台目录刷新即可看到公开产品；分页可能因产品数量增加而变化。

后台「媒体」保存已上传的图片，直接复用即可。示例图库共 6 张，12 款虚构产品中部分共用图片。媒体本身是公共文件，不要上传隐私或公司资料。

## 添加分类、修改说明页面

- 分类：左侧「产品」→「产品分类」→填写名称和英文别名→添加。回产品编辑页勾选分类再更新。
- 关于与联系页：左侧「页面」→「所有页面」→点击对应页面→修改正文→更新。
- 导航顺序：左侧「外观」→「菜单」→选择「主导航」，拖动菜单项并保存。
- 首页大标题和主视觉布局是子主题模板代码，不由后台首页正文控制；求职演示时可以在 `themes/nrc-child/front-page.php` 解释这一点。

## 发布、草稿、私密和密码保护

普通目录只展示公开且没有设置密码的已发布产品。草稿与私密内容不展示给游客。密码保护产品不在目录出现；通过详情链接访问时先显示密码表单，验证前不展示自定义型号、图片和正文。管理员登录不等于已经输入了该内容的密码。

管理员、编辑可以管理其他人的产品；作者可以编辑、发布和删除自己的产品；贡献者只能编辑自己的未发布内容、不能发布；订阅者不能管理产品。型号保存还检查具体产品权限和表单 nonce。当前交付仅保留一个本地管理员，测试中的临时角色账号已清理。

## 收工与下次继续

PowerShell 进入项目目录后运行 `docker compose stop` 即可停止且保留数据。下次用 `docker compose up -d --wait` 再打开前台。不要把“停止”理解为删除卷。

## 五分钟面试路线

1. **0–1 分钟**：首页 → 目录 → 第二页 → 详情，说明这是虚构 Portfolio Demo。
2. **1–2 分钟**：登录 → 产品 → 修改合法型号 → 更新 → 前台验证。
3. **2–3 分钟**：输入非法型号，看红色错误；解释 nonce、对象权限和“正文可能已保存”。
4. **3–4 分钟**：打开插件和子主题文件，指出业务逻辑与外观分离、没有修改父主题。
5. **4–5 分钟**：展示 `docs/restore-drill.md`、集成测试输出和恢复保存截图；说明实际做过恢复及插件停用故障演练，没有生产运维成果声明。
